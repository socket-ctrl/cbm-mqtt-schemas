# 煤层气智能井场 MQTT 协议 JSON Schema

本仓库是《煤层气智能井场 MQTT 通信协议（对外通用版）》的 JSON Schema 正式发布库，用于报文格式校验、接入方开发对接与协议变更协作治理。

## 仓库内容

```
├── docs/       协议文档原文（对外通用版，是 schema 的唯一规范依据）
├── schema/     JSON Schema（按版本目录组织，旧版本目录发布后不可变）
│   └── v1.2/
│       ├── common/   通用消息头、可复用定义（时间戳/枚举/指令结构）
│       ├── up/       网关→平台：心跳、生产数据、ack、result、算法上报
│       └── down/     平台→网关：控制指令、连锁指令、算法配置
└── .github/    协作流程配置（Issue 模板、CI、PR 模板）
```

## 版本策略

- Schema 版本跟随协议文档版本，目录即版本（如 `schema/v1.2/`）
- 已发布版本目录**不可修改**，变更一律通过新版本目录或版本内兼容性修订进行
- `ver` 字段前缀相同的报文向下兼容（如 1.1 兼容 1.0），不同前缀存在不兼容内容

## 校验方式

Schema 采用 JSON Schema Draft 2020-12，`$id` 基址为 `https://socket-ctrl.github.io/cbm-mqtt-schemas/schema/v1.2/`（经 GitHub Pages 发布，Pages 部署完成后即可通过 URL 直接引用）。可用任何支持 2020-12 的校验库（如 [ajv](https://ajv.js.org/)）对 MQTT payload 进行校验。

## 协作流程（外部接入方请阅读）

1. **提 Issue**：通过 Issue 模板提交（协议变更申请 / 缺陷反馈 / 扩展申请），语言中文，须附涉及的 Topic 与报文示例
2. **评审**：协议维护方在 Issue 中评审定级，确认必要性、影响范围与版本归属
3. **提 PR**：评审通过后 fork 本仓库修改 schema 与文档，PR 须关联 Issue（`Closes #n`），CI 校验通过
4. **审核合并**：由协议维护方审核合并，随版本发布（GitHub Release + changelog）

直接推送受保护分支会被拒绝，所有变更必须走 PR。

## 分支模型

| 分支   | 用途   | 保护规则                      |
| ------ | ------ | ----------------------------- |
| main   | 生产态 | 禁止直推，须 1 个审核 + CI 通过 |
| develop | 开发态 | 禁止直推，须 1 个审核 + CI 通过 |
